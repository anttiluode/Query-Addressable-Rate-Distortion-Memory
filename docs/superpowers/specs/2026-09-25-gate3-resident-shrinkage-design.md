# QARDM Gate 3 — Resident directional sensitivity with shrinkage

Date: 2026-09-25

## Why this gate exists

Gate 1 showed that a compression policy aimed at future query consequence can beat reconstruction at moderate budgets. Gate 2 then showed that finite query evidence creates a serious generalization problem: larger calibration banks greatly reduced calibration optimism, but only modestly and inconsistently improved the final compressed memory. A fixed reconstruction hedge was more effective, especially at 30% storage, but still missed the preregistered cross-seed criterion.

The next question is therefore not simply whether more past queries help. It is whether the *query history itself can be compressed into a resident directional statistic*, and whether that statistic should explicitly encode uncertainty when evidence is sparse.

This gate deliberately does **not** attempt a full online memory system. Original episodes remain available while the allocator compares candidate compression moves, exactly as in Gates 1–2. Gate 3 isolates one smaller claim: can the raw query log be replaced by a fixed-size directional sensitivity state, and does shrinkage make that state generalize better?

Development probes used only seeds `97..99`. They selected the representation below and a frozen pseudo-count `kappa = 1.0`. Gate 3 scoring uses fresh seeds `300..311`.

## Resident sensitivity state

For each original episode `i` and payload coordinate `j`, accumulate only the squared probe component from past accesses addressing that episode:

```math
S_{ij} = \sum_{q \to i} q_j^2.
```

Also retain the access count `n_i`. The raw query objects, their target values, and their individual cues are discarded after this state is built.

The state is diagonal: it does not retain cross-coordinate terms `q_j q_k`. This is intentional. It is a cheap first test of whether **directional importance** can survive as a resident sufficient-statistic-like object before paying for a full covariance matrix.

For a candidate compressed memory `M`, read it at the original episode key and define

```math
\Delta_i(M) = \hat x_i(M) - x_i.
```

The raw resident sensitivity distortion is

```math
L_{raw}(M) = \frac{1}{N_q}\sum_{i,j} S_{ij}\,\Delta_{ij}(M)^2.
```

This is not equal to the original query-bank loss because it drops cue jitter, target-level query instances, and off-diagonal probe covariance. That approximation is part of the test.

## Shrinkage prior

Let

```math
\alpha = \frac{1}{N_q D}\sum_q \lVert q\rVert^2,
```

where `D=12` is payload dimension. `alpha I` is therefore an isotropic prior with the same average per-coordinate probe energy as the observed history.

Gate 3 freezes

```math
\kappa = 1.0
```

pseudo-query per episode, giving

```math
L_{shrink}(M)
= \frac{1}{N_q + \kappa N_e}
  \sum_{i,j}(S_{ij}+\kappa\alpha)\,\Delta_{ij}(M)^2.
```

The denominator does not change greedy operation ordering, but keeps the reported loss scale interpretable.

`kappa=1` was chosen before Gate 3 scoring. It is not the best value in every development budget; its interpretation is simply one isotropic pseudo-observation per episode. No per-budget or post-result `kappa` selection is allowed.

## Frozen evaluation worlds

- Seeds: `300..311` inclusive (12 worlds).
- These seeds were not used in Gates 1–2, Claude's post-Gate check, or Gate 3 development probes before this document was written.
- Episode generation, query distribution, reader temperature, scalar accounting and legal memory operations remain unchanged.
- A single ordinary `1x` calibration bank generated by `make_calibration_bank(..., multiplier=1)` is treated as **past access history**.
- The independent evaluation bank from `make_world(seed)` is the future query bank and never enters allocation.

## Estimator-state accounting

The diagonal sensitivity state contains:

- `24 x 12 = 288` directional accumulators;
- 24 episode access counts;
- one global `alpha` scalar.

Total: **313 scalar values**, fixed after the history is summarized.

For comparison, the 1x raw query history contains 360 query instances with 4 cue coordinates, 12 probe coordinates and one target scalar each: 6,120 scalar values before Python/object overhead.

This Gate does **not** charge the 313 estimator scalars against the 432-scalar memory payload budget. Gates 1–2 likewise treated the calibration estimator as external to the memory payload budget. The purpose here is to test whether the log can be summarized at all. A later gate must include controller/estimator state in the total budget before making an end-to-end memory-efficiency claim.

## Allocators and baselines

All policies use the same original episodes, candidate operations and payload scalar budget.

### Raw resident sensitivity

Uses `L_raw` above with no prior (`kappa=0`).

### Shrunk resident sensitivity

Uses `L_shrink` with frozen `kappa=1.0`.

### Gate 2 baselines

Report unchanged:

- `query_rd` using the full 1x raw calibration bank;
- `hedged` using `query_mse + reconstruction_mse` with weight 1.0;
- pure reconstruction.

These baselines receive no Gate 3 evaluation queries.

## Budgets

Full memory remains 432 charged payload scalars.

- 60%: 259 scalars;
- 50%: 216 scalars;
- 40%: 172 scalars;
- 30%: 129 scalars.

## Measurements

For every seed and budget record held-out evaluation MSE for:

- raw resident sensitivity;
- shrunk resident sensitivity;
- query 1x;
- Gate 2 hedge;
- reconstruction.

For raw and shrunk sensitivity also record:

- sensitivity objective value of the final memory;
- operation ledger;
- retained hot-family fine-detail count.

The receipt also records resident-state scalar count and raw-history scalar count.

## Primary criteria

Gate 3 is classified `PASS_RESIDENT_SHRINKAGE` only if all conditions hold on seeds `300..311`.

### A. Shrinkage improves the resident metric under stress

At both 40% and 30% budgets:

1. shrunk sensitivity has lower **mean held-out evaluation MSE** than raw sensitivity; and
2. shrunk sensitivity beats raw sensitivity in at least **8 of 12** seeds.

### B. Resident shrinkage remains competitive with conservative baselines

At both 40% and 30% budgets, shrunk sensitivity mean held-out evaluation MSE must be no more than **5% worse** than **each** of:

- the frozen Gate 2 hedge mean; and
- reconstruction mean.

This is deliberately stronger than comparing only to whichever baseline happens to be weaker.

### C. Shrinkage does not erase the useful query-aware regime

At both 60% and 50% budgets, shrunk sensitivity mean held-out evaluation MSE must be no more than **10% worse** than pure 1x `query_rd` mean.

## Secondary analyses

Report without changing classification:

- raw sensitivity versus full raw query-bank allocation;
- shrunk sensitivity versus Gate 2 hedge seed-by-seed;
- operation counts and hot-family fine-detail retention;
- whether shrinkage changes `forget` more than `merge` or `coarsen`;
- correlation between per-seed raw-to-shrunk improvement and the anisotropy/noisiness of the resident sensitivity state.

## Interpretation boundaries

A pass would support:

> Past query demand can be compressed into a fixed-size directional sensitivity state, and a small isotropic prior can improve the out-of-sample memory decisions made from that state.

It would not establish:

- that the diagonal statistic is sufficient in general;
- that `kappa=1` is optimal or transferable;
- a true online streaming allocator;
- that the 313-scalar controller cost is negligible;
- a biological consolidation mechanism;
- a transformer or visual-memory improvement.

A failure is equally useful. If raw sensitivity fails badly, the query log contains important cue/covariance information that the diagonal state discarded. If shrinkage fails, reconstruction's Gate 2 benefit is not captured by a simple isotropic pseudo-count.
